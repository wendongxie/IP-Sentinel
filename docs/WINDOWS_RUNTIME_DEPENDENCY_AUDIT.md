# Windows 运行库依赖审查

旧基线的 42 个文件均由 PyInstaller 从另一软件的 libheif 目录收集。收集清单能定位文件来源，无法单独区分 PATH、PyInstaller 搜索目录和各个 hook 对当次解析的贡献。原构建的完整环境变量快照未留存。

当前支持 Windows 10 1809 及以上和 Windows 11。构建时在独立虚拟环境调用 PyInstaller，仅在冻结阶段将 PATH 限于虚拟环境 Scripts、System32 和 Windows 目录，使用独立 TEMP/TMP。spec 审查 Analysis 的实际结果，过滤系统 UCRT、core/crt API Set 和已有的系统 ICU 项，拒绝收集来自构建解释器及虚拟环境目录之外的原生 DLL/PYD。Windows 继续解析应用和插件的系统合约导入。此操作针对冻结收集结果，旧证据和操作系统文件均保留。

MSVC C++ 运行库另行审核。部署时使用经核实的 Microsoft Visual C++ x64 Redistributable 或获授权的官方应用本地运行库文件。来自 Python 或 wheel 的直接路径及匹配哈希仍需追溯其再分发权利。系统 UCRT 通过 Windows 维护。官方说明见 [Microsoft C++ 部署](https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files) 和 [Windows API Sets](https://learn.microsoft.com/en-us/windows/win32/apiindex/windows-apisets)。

## Windows 10 内部验证

在 Windows 10 专业版 19045、CPython 3.12.16、OpenSSL 3.5.9 和哈希锁定的 wheel 环境重建。PyInstaller 日志显示 hook 加入了隔离环境内的 shiboken6 和 PySide6 目录。新载荷的 76 个原生文件与各自构建输入的 SHA-256 全部一致，均位于基础 Python、隔离虚拟环境或本次构建目录。另存的[内部文件清单](../release-compliance/windows-native-internal.json)记录每个文件的分组、路径、哈希和来源。旧 115 项证据保留。

按相对路径比较，54 项移出、15 项新增、25 项同路径内容变化。42 个目标文件全部排除；另有一个不同来源的系统 CRT 合约 `api-ms-win-crt-utility-l1-1-0.dll` 同样由系统提供。Qt 和绑定的若干 DLL 归入各包的子目录，隔离环境不再收集旧包中的 CFFI 扩展。这些变化同时反映基础 Python 和虚拟环境的不同。

保留了五种 MSVC 运行库：MSVCP140、MSVCP140_1、MSVCP140_2、VCRUNTIME140、VCRUNTIME140_1。其中 8 个部署路径有官方 wheel 成员匹配，另 2 个 VCRUNTIME 文件来自基础 Python。未做跨目录去重；仍需核对最终选定运行时的 Microsoft 分发授权。

冻结包窗口/托盘/图标与窗口唤醒测试通过，使用 Windows 平台插件。真实探测与临时 SQLite 写读测试通过；分协议检查得到 IPv4，IPv6 未取得出口。现有 20 项测试通过，包括模拟 Telegram 与企业微信通知。Windows 11 和真实机器人发送未验证。正式发布仍要求合格的 OpenSSL 运行时、最终载荷审查、LGPL 对应源码及人工复核；Qt 库部署位置变化后须在最终产物重新验证替换步骤。
